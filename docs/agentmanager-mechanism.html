读取：一个源，三种落盘方式

skills 与提示词共享同一份内容：前者用 Windows junction 把 agent 目录指回源，后者优先硬链接（系统不允许时退化为符号链接或副本）。MCP 与 hooks 没有这种共享方式，按各 agent 的格式写同步副本。资产矩阵不缓存：每次读取都重扫目录、重算哈希，所以页面上的每个状态都能在磁盘上复现。

写入：先快照，再落盘

所有写操作先为受影响路径（以及将要新建的路径）建快照，再以临时文件 + rename 落地。提示词与配置文件另外带 etag：如果文件在别处被改过，保存返回 409，界面保留草稿而不是覆盖。写入失败时按快照还原；还原本身也会先建一份安全快照，所以误还原还能撤销。

商店：先隔离，再进源

skill 与 MCP 的安装都从注册表开始，但进入源之前各有一道隔离。skill 先读 manifest，把 ZIP 下载到 data/tmp，校验 sha256、ZIP 结构、必须包含 SKILL.md、路径不许越界，全部通过才整体 move 进源；MCP 在安装弹窗里补齐注册表要求的必填变量，然后写归一化定义并同步。两边同名已存在时都返回 409，不覆盖。

边界

  • 扫描只读。 页面上的数字必须能在磁盘上复现；缓存页的清理是移动到回收站，不是删除。
  • 写操作可回滚。 配置写前快照，缓存清理进回收站；只有「清空回收站」是不可逆动作。
  • 商店不执行内容。 skill 不会被运行，MCP server 不会被启动，同名条目不覆盖。
